## 3. 用例描述

### UC-01 登录系统

| 属性 | 值 |
|------|-----|
| 用例名称 | 登录系统 |
| 参与者 | 系统管理员 |
| 前置条件 | 管理员凭证已配置（环境变量）；Session 已过期或不存在 |
| 后置条件 | Session 创建成功，跳转首页 |

**主流程**：
1. 管理员访问 `/login.html`
2. 输入用户名和密码
3. 点击"登录"按钮
4. 系统校验凭证（BCrypt 比对）
5. 凭证正确 → 创建 Session，跳转 `/`

**替代流程**：
- 4a. 凭证错误 → 显示"账号或密码错误"提示，停留在登录页
- 4b. CSRF Token 缺失 → 返回 403

### UC-02 人员档案管理

#### UC-02a 新增人员

| 属性 | 值 |
|------|-----|
| 用例名称 | 新增人员 |
| 参与者 | 系统管理员 |
| 前置条件 | 已登录 |
| 后置条件 | `employees` 表新增一条记录 |

**主流程**：
1. 管理员点击"新增人员"按钮
2. 填写：工号（唯一）、姓名、部门、职位
3. 提交表单
4. 系统校验字段非空与长度限制
5. 插入数据库，状态默认为"在职"

**替代流程**：
- 4a. 工号重复 → 返回"工号已存在"
- 4b. 字段超长/为空 → 返回具体字段提示

#### UC-02b 启停人员

|------|-----|
| 前置条件 | 已登录；目标人员存在 |
| 后置条件 | `active` 字段更新 |

**主流程**：
1. 管理员点击"停用"或"启用"按钮
2. 二次确认弹窗
3. 确认后更新 `active` 字段
4. 停用后该人员禁止人脸打卡和录入

### UC-03 人脸录入

| 属性 | 值 |
|------|-----|
| 用例名称 | 人脸录入 |
| 参与者 | 系统管理员 |
| 前置条件 | 已登录；目标人员存在且在职 |
| 后置条件 | `employees.descriptor` 字段写入 128 维人脸特征 |

**主流程**：
1. 管理员在人员列表点击"录入人脸"
2. 系统跳转打卡页，显示该员工信息
3. 点击"开启摄像头" → 浏览器请求摄像头权限
4. face-api.js 加载 TinyFaceDetector + Landmark68 + RecognitionNet 模型
5. 管理员让该员工正对摄像头，画面中仅一张脸
6. 点击"采集并保存"
7. 前端提取 128 维描述符，POST 到后端
8. 后端校验描述符合法性（128 维、归一化、值域）
9. 后端与已录人脸比对欧氏距离，检查重复
10. 保存到 `descriptor` 字段

**替代流程**：
- 4a. 摄像头权限被拒 → 显示提示
- 6a. 画面中无人脸/多张脸 → 拒绝采集
- 8a. 描述符无效 → 返回错误
- 9a. 欧氏距离 < 0.5 与已有人脸重复 → 返回"此人脸已被其他人员录入"
- 9b. 人员已停用 → 返回错误

### UC-04 人脸打卡（核心）

| 属性 | 值 |
|------|-----|
| 用例名称 | 人脸打卡 |
| 参与者 | 系统管理员（代员工打卡） |
| 前置条件 | 已登录；目标人员已录入人脸且在职 |
| 后置条件 | `attendance` 表新增或更新一条记录 |

**主流程**（上班签到）：
1. 管理员选择"上班签到"模式
2. 点击"开启摄像头" → 模型加载 → 画面就绪
3. 员工走到摄像头前，画面中单张人脸清晰
4. 点击"开始识别"
5. 前端提取 128 维描述符，POST 到 `/api/recognize`
6. 后端遍历所有在职人员的 `descriptor`，计算欧氏距离
7. 找出最佳匹配（距离最小）和次佳匹配
8. 校验：最佳距离 ≤ 阈值 **且** 次佳 - 最佳 ≥ 0.05
9. 检查今日是否已签到（UNIQUE 约束）
10. 判断时间：晚于设置的上班时间 → 状态 = "迟到"，否则 = "正常"
11. INSERT 到 `attendance`，返回匹配结果

**主流程**（下班签退）：
1-8. 同上，匹配成功
9. 检查今日是否已签到（必须先签到）
10. 检查今日是否已签退（防重复）
11. 检查时间：早于设置的下班时间 → 状态追加"早退"
12. UPDATE `check_out` 字段和状态

**替代流程（UC-04e 打卡拒绝）**：
| 场景 | 拒绝条件 | 返回消息 |
|------|----------|----------|
| 画面无人脸 | `faces.length === 0` | "未检测到清晰人脸" |
| 多人脸 | `faces.length > 1` | "检测到多张人脸，请确保只有本人在画面中" |
| 匹配距离超阈值 | `best > threshold` | "未找到可靠匹配" |
| 模糊匹配 | `second - best < 0.05` | "未找到可靠匹配" |
| 重复签到 | `attendance` 已存在 | "今日已签到" |
| 重复签退 | `check_out` 已存在 | "今日已签退" |
| 未签到即签退 | `attendance` 不存在 | "请先完成上班签到" |
| 停用人员 | `active = FALSE` | "未找到可靠匹配" |

### UC-05 考勤总览

| 属性 | 值 |
|------|-----|
| 用例名称 | 考勤总览 |
| 参与者 | 系统管理员 |
| 前置条件 | 已登录 |
| 后置条件 | 实时展示今日应到/出勤/异常/未签到统计 |

**主流程**：
1. 管理员进入首页
2. 系统加载全部人员和近 60 天考勤记录
3. 实时计算今日统计卡片
4. 渲染今日出勤环形图（v1.1）、7/30 天趋势图（v1.1）
5. 展示今日考勤记录表格（含搜索筛选）

### UC-06 考勤记录查询

| 属性 | 值 |
|------|-----|
| 用例名称 | 考勤记录查询 |
| 参与者 | 系统管理员 |
| 前置条件 | 已登录 |

**主流程**：
1. 管理员进入"考勤记录"页面
2. 选择日期范围（不超过一年）
3. 可选：输入搜索关键词（姓名/工号）
4. 可选：选择部门、状态筛选
5. 点击"查询" → 后端返回结果
6. 前端分页展示（每页 10 条）

**替代流程**：
- 2a. 日期范围超过一年 → 返回"请选择不超过一年的有效时间范围"
- 2b. 起始日期晚于结束日期 → 返回错误

### UC-07 异常核实

| 属性 | 值 |
|------|-----|
| 用例名称 | 异常核实 |
| 参与者 | 系统管理员 |
| 前置条件 | 已登录；目标记录存在；状态 ≠ "正常"；尚未核实 |
| 后置条件 | `resolved = true`，`note` 写入核实说明，`status` 不变 |

**主流程**：
1. 管理员点击异常记录的"处理异常"
2. 弹出详情弹窗，显示人员/日期/状态
3. 填写核实说明（1-300 字）
4. 提交 → 后端 UPDATE `resolved = true, note = ?`
5. 确认成功，关闭弹窗

**替代流程**：
- 4a. 记录已核实 → 返回"记录已处理或无需处理"
- 4b. 记录状态为"正常" → 不可核实

### UC-09 系统设置

| 属性 | 值 |
|------|-----|
| 用例名称 | 系统设置 |
| 参与者 | 系统管理员 |
| 前置条件 | 已登录 |
| 后置条件 | `settings` 表更新，后续打卡按新规则判断 |

**主流程**：
1. 管理员进入"系统设置"页面
2. 修改上班时间（HH:mm）、下班时间（HH:mm）、识别阈值（0.30-0.60）
3. 点击"保存"
4. 校验：下班时间必须晚于上班时间；阈值在范围内
5. UPDATE `settings`

**替代流程**：
- 4a. 下班时间 ≤ 上班时间 → 返回"下班时间必须晚于上班时间"
- 4b. 阈值超范围 → 返回"识别距离阈值应在 0.30–0.60 之间"
- 注意：设置变更**不影响**已存在的考勤记录状态
